# 1. 개요
---
### 1.1 목적
- 신규 가입 사용자가 **좌석 추천에 필요한 선호 데이터**를 최초 1회 수집하여 추천 품질을 확보합니다.
- 좌석 추천 기능 사용의 전제 조건으로서 **온보딩 완료를 강제**합니다.
### 1.2 대상
- 카카오 소셜 로그인 완료 후, 서비스 최초 진입 사용자(온보딩 미완료 사용자)
### 1.3 범위
- 온보딩 페이지(선호 블록 선택 + 선호 구역/좌석 3순위 설정) 
- 필수 선호도/선택 선호도 수집 
- 입력 값 저장 및 내블럭 초기 목록 생성 
- 온보딩 완료 처리 및 이후 경로 이동
# 2. 사용자 시나리오 및 플로우
- 유저 플로우
    ```mermaid
    flowchart TD
      A[카카오 로그인 또는 회원가입 완료] --> B{온보딩 완료 여부}
      B -- 완료 --> H[홈 또는 직전 페이지 이동]
      B -- 미완료 --> C[온보딩 페이지 진입]
    
      C --> D[필수 선호도 입력]
      D --> E[선택 선호도 입력]
      D -- 건너뛰기 --> F[시작하기 클릭]
      E --> F[시작하기 클릭]
    
      F --> G[선호도 저장]
      G --> I[온보딩 완료 처리]
    
    ```
    
---
### 2.1 가입 직후 온보딩
1. 카카오 로그인/회원가입 완료
2. 선호 좌석 온보딩 진입(스킵 불가)
3. 선호 블럭 ㅇ선택(최대 10개, 필수) + 선호 구역/좌석 1~3순위 입력(필수) + 선택 선호도(선택)
4. 저장 및 내블럭 목록 생성/조회
5. 온보딩 완료 → 홈(또는 추천 기능 진입 화면) 이동
### 2.2 온보딩 미완료 사용자(재진입)
- 사용자가 앱/웹 종료, 네트워크 실패, 중도 이탈 후 재접속 시
1. 로그인 완료 후 온보딩 상태 확인
2. `onboarding_status != COMPLETED` 이면 온보딩 페이지로 강제 이동
3. 이전 입력이 저장되어 있으면 이어서 수정/완료
### 2.3 기존 사용자(완료 후 수정)
- 온보딩 완료 이후에는 설정(마이페이지)에서 선호도 수정 가능(권장)
- 단, “가입 직후 온보딩”은 1회 완료가 필수이며 완료 전에는 핵심 기능 진입 불가
# 3. 기능 명세
---
### 3.1 진입 조건 및 라우팅
- 진입 조건
    - 회원가입 완료
    - `onboarding_status != COMPLETED`
- 라우팅
    - 온보딩 미완료: 선호 좌석 온보딩으로 강제 이동
    - 온보딩 완료: 홈(또는 직전 페이지) 이동
### 3.2 화면 구성
- 화면: 선호 좌석 온보딩
- 구성
    - 좌측 진행 단계, 안내 문구(예 : “추천 좌석을 위한 선호 설정”)
    - 우측 선호도 조사
	    - 섹션 A(필수) : 경기장 블록 맵 위에서 블록을 직접 탭/클릭하여 선택
		    - CTA : 다음
		- 섹션 B(필수): 선호 구역/좌석 1~3순위 입력
	        - CTA : 이전 / 다음
		- 섹션 C(선택): 선택 선호도 입력
	        - CTA : 이전 / 건너뛰기 / 시작하기
### 3.3 내블럭 선택
- 목적: 사용자가 관심 있는 블록을 직접 지정하여 티켓팅 시 "내블럭" 목록의 기반 데이터로 활용 
- UI 
	- 경기장 블록 맵(구장별 블록 구성 이미지) 위에서 블록을 직접 탭/클릭하여 선택 
	- 선택된 블록은 하이라이트 표시 
	- 현재 선택 수 표시 (예: "3 / 10 선택") 
- 입력 제약 
	- 최소: 1개 
	- 최대: 10개
	- 동일 블록 중복 선택 불가 
	- 최대(10개) 초과 시도 시: 선택 차단 + "최대 10개까지 선택 가능합니다" 인라인 안내 
- 저장 형태: `preferred_blocks: block_id[]` (최대 10개)
### 3.4 필수 선호도 입력 (필수)
> 사용자가 선택한 내블럭(최대 10개)의 우선순위(BlockScore)를 결정하기 위한 
> 블록 레벨 선호 데이터를 수집한다.
- **[Q1] 어디에서 보고 싶으신가요?** *(zone_area 매핑)* 
	- 선택 방식: 단일 선택 (1순위만) 
	- 선택지: 중앙 / 1루 내야 / 3루 내야 / 1루 외야 / 3루 외야 / 외야 중앙 
- **[Q2] 응원하는 구단이 있으신가요?** *(cheering_team 매핑)* 
	- 선택 방식: 드롭다운 단일 선택 
	- 선택지: KIA / 삼성 / LG / 두산 / KT / SSG / 롯데 / 한화 / NC / 키움 / 없음 
	- 활용: 응원 구단 기반으로 홈/원정 응원석 블록 위치 산출에 활용 
- **[Q3] 응원석 근방 자리를 선호하시나요?** *(cheer_zone_preference 매핑)* 
	- 선택 방식: 단일 선택 
	- 선택지: 응원석 인접 / 응원석 비인접 
	- 활용: Q2의 응원 구단 응원석 블록 기준으로 인접/비인접 블록 우선순위 결정
- 제약
	- 3문항 모두 필수 응답
	- Q2에서 "없음" 선택 시 Q3 비활성화 및 cheer_zone_preference = NONE 저장
### 3.5 선택 선호도 입력(선택)
> 현재 블록 추천 로직에서 직접 사용하지 않으나, 
> 추후 개인화된 블록 추천 고도화를 위해 미리 수집해두는 데이터다. 
> 미입력 시 기본값(UNKNOWN/NONE)으로 저장한다.
- - 입력 항목 
	- 좌석 타입: 통로 선호 / 중앙 선호 / 무관 
	- 관람 환경: 그늘 선호 / 햇빛 무관 / 무관 
	- 관람 분위기: 응원 강함 / 조용함 / 무관 
	- 시야 민감도: 안전망 민감 / 난간·기둥 민감 / 보통 / 둔감 
	- 가격 민감도: 낮을수록 선호 / 무관
### 3.6 저장 및 완료 처리
- 저장 트리거: 사용자가 시작하기 클릭
- 처리
    1. 입력값 검증(필수/중복/형식)
    2. 선호도 저장 API 호출
    3. 성공 시
        - `onboarding_status = COMPLETED` 처리
        - 추천 생성 트리거(동기 응답 또는 비동기 Job 방식)
### 3.7 예외/에러 처리
- 필수 미선택
    - CTA 비활성화 + 해당 필드 인라인 안내
    - 내블럭 미선택 시: "관심 블록을 1개 이상 선택해주세요" 안내
- 네트워크/서버 오류
    - 저장 실패: “저장에 실패했습니다. 다시 시도해 주세요.” + 재시도
    - 추천 실패: 선호도 저장/완료는 유지하되, 추천 영역은 재시도 버튼 또는 기본 가이드 노출
# 4. 정책
---
### 4.1 온보딩 강제 진행 정책
- 가입 직후 온보딩은 **스킵 불가**
- 온보딩 미완료 시, 재로그인/재진입 시마다 온보딩으로 강제 이동
### 4.2 3순위 및 중복 정책
- 3순위 입력
    - 기본 정책: 1~3순위 모두 필수 입력
- 중복
    - 동일한 구역/좌석 조합의 중복은 불가
    - 구역 단위만 수집하는 초기 버전에서는 **구역 중복 금지**를 기본으로 적용한다.
    - 추후 열/좌석 위치까지 세분화되면 “구역 중복 허용 + 세부 값 중복 금지”로 확장 가능하다.
### 4.3 데이터 저장 정책(스키마 개요)
- 사용자 단위 선호도(공통 선호)로 저장한다.
- 필수/선택 분리 저장
    - required_preferences: rank1, rank2, rank3
    - optional_preferences: price_sensitivity, aisle_preference, obstruction_sensitivity, party_size 등
- 선택 항목 미입력 시 기본값은 UNKNOWN 또는 NONE로 저장하여, 추천 로직이 결측을 명시적으로 처리 가능하도록 한다.

### 4.4 개인정보/동의 고지 정책
- 선호도 데이터는 개인 성향 정보로 취급 가능하므로 다음을 준수한다.
    - “추천 제공을 위한 선호도 수집” 목적 고지(온보딩 화면 내 간단 문구)
    - 선택 항목은 “선택”임을 UI로 명확히 구분
### 4.5 접근/권한 정책
- 온보딩은 로그인 사용자만 접근 가능하다.
- 다른 사용자 선호도 접근은 불가하며, 본인만 조회/수정 가능하다.

## 1. 대기열의 목적과 원칙

대기열은 예매 오픈 순간 수천 명이 동시에 서버에 접근하는 상황에서 **서비스 안정성을 유지하면서 공정한 순서를 보장**하기 위한 장치다.

- 서버가 처리할 수 있는 속도에 맞춰 사용자를 순차적으로 예매 화면에 진입시킨다.
- 진입 순서는 대기열 등록 시각 기준 선착순으로 처리한다.
- 대기열을 통과한 사용자에게는 일정 시간 동안 예매 진입권(Admission Token)을 부여한다.

---

## 2. 대기열 발동 기준

대기열 발동은 서버 부하를 판단하는 두 가지 주요 지표를 기준으로 한다. 하나라도 초과 시 즉시 대기열을 활성화한다.

|지표|설명|
|---|---|
|동시 접속자 수 (CCU)|예매 오픈 시점에 동시에 접속한 사용자 수|
|초당 요청 수 (TPS)|대기열 진입 요청 기준|

대기열이 활성화된 이후에는 아래 보조 지표를 추가로 참고하여 통과 속도를 조절한다.

- 대기 중인 사용자 수 적체 규모
- 서버 CPU 사용률

> ⚠️ 구체적인 임계치 수치는 부하 테스트 완료 후 확정한다. → [[부하테스트 시나리오]] 2부 결과 참조

## 3. 사용자 대기열 상태 흐름

예매 오픈 시 대기열이 활성화된 경우, 사용자는 아래 순서로 상태가 전환된다.

```
예매하기 클릭
    ↓
대기열 등록 (등록 시각 기준 순번 부여)
    ↓
대기 중 — 현재 순위 및 예상 대기 시간 안내
    ↓
통과 준비 완료 (READY) — 60초 이내 예매 화면 진입 필요
    ↓
예매 화면 진입 (15분 이내 예매 완료 필요)
```

### 대기 중 상태 업데이트 주기

대기 순위에 따라 상태 갱신 빈도를 다르게 적용한다. 순위가 낮을수록 갱신 빈도를 줄여 서버 부하를 분산한다.

|대기 순위|상태 업데이트 주기|
|---|---|
|1 ~ 100위|1.5초마다|
|101 ~ 1,000위|3초마다|
|1,001위 이상|5초마다|
|통과 준비 완료 상태|1초마다 (즉시 진입 유도)|

### 통과 처리 기준

- 대기열은 매초 최대 100명까지 예매 화면 진입을 허용한다.
- 이미 통과 준비 완료(READY) 상태인 사용자가 많을 경우, 신규 통과 인원이 줄어들 수 있다.

---

## 4. 통과 후 진입권 정책

대기열을 통과한 사용자에게는 예매 진입권이 발급된다.

|항목|기준|
|---|---|
|통과 준비 완료 유지 시간|**60초** — 이 시간 안에 예매 화면으로 진입해야 한다|
|예매 진입권 유효 시간|**15분** — 진입 후 Hold 및 결제까지 완료해야 한다|
|미응답 시 처리|60초 초과 시 진입권 만료, 재진입 시 대기열 맨 뒤 배치|

> 통과 준비 완료 알림을 받은 후 **60초 이내에 예매 화면으로 이동**해야 한다. 이를 놓치면 대기열에 재등록되며 순번이 초기화된다.

---

## 5. 재진입 처리 기준

사용자가 대기열 도중 페이지를 이탈하거나 재접속하는 경우 아래 기준을 따른다.

- 기존 대기 순번은 초기화되며, 재진입 시각 기준으로 맨 뒤에 새로 배치된다.
- 통과 준비 완료(READY) 상태였더라도 만료 후 재진입하면 순번이 초기화된다.
- 이미 진입권을 사용 중인 경우(예매 진행 중)에는 재진입이 제한된다.

|---|---|

|사용자 자발적 이탈|사용자가 명시적으로 대기열을 나가거나 브라우저를 종료할 때|

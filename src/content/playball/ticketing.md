# 1. 문서 개요
---
### 1.1 목적
- 사용자가 특정 경기의 좌석을 **선택·확보·구매**할 수 있는 티켓팅 기능을 정의한다.
- 좌석 확보 실패의 주요 원인인 **동일 좌석 집중 트래픽**을 완화하기 위해, 좌석 상태 관리/경합 처리/추천·대체 제안을 포함한다.
### 1.2 In scope
- 경기/예매 오픈 정보 노출 
- 좌석 맵 조회(기본 탐색)
- 내블럭 노출(온보딩 선택 블록 기반, 선호 점수 정렬)
- 추천좌석 ON/OFF 토글로 모드 전환(티켓팅 도중 포함) 
- 내블럭 리스트 및 블록별 잔여 좌석 표시, 새로고침
- 블록 카드 상태별 좌석맵 렌더링(기본/hover/focus) 
- 블록 선택 → 연석 자동배정 → Hold 
- 좌석 홀드(임시 배정) 및 타임아웃 
- 결제 단계 진입 직전(주문 생성)까지
### 1.3 Out of scope
- PG 결제 처리 상세(카드/간편결제/환불/부분취소 등)
- 정산, 세금계산서, 쿠폰/프로모션 상세
### 1.4 용어 정의
- **좌석 상태**: `AVAILABLE`(판매 가능) / `HELD`(임시 확보) / `SOLD`(판매 완료) / `BLOCKED`(판매 불가)
- **Hold**: 사용자에게 좌석을 일정 시간 임시로 배정하여 결제 시도 가능하게 하는 락
- **내블럭**: 온보딩에서 사용자가 직접 선택한 최대 10개의 블록 목록. 선호 점수 및 잔여 좌석 기반으로 정렬되어 노출됨
- **블록 추천**: 내블럭 목록을 선호 데이터 점수 기반으로 정렬하여 제공하는 블록 단위 추천 결과
- **연석 자동배정**: 사용자가 블록을 선택하면 해당 블록 내에서 인원 수에 맞는 연석을 시스템이 자동으로 선택하는 방식
# 2. 사용자 시나리오
---
### 2.1 추천좌석 토글 ON으로 진입
1. 사용자가 경기 상세 페이지 진입
2. 추천좌석 보기 토글을 ON으로 설정
3. 예매하기 클릭
4. 좌석 선택 화면 진입 시 **내블럭 선택 화면(추천 모드)** 노출
5. 사용자가 **내블럭 카드를 선택** → **해당 블록 내 연석 자동배정** → Hold 요청
6. Hold 성공 → 주문서(결제 직전) 진입
    - Hold 실패 → 실패 모달 노출 + 좌석 선택 재시도
### 2.2 추천좌석 토글 OFF로 진입(기존 좌석 맵 방식)
1. 사용자가 경기 상세 페이지 진입
2. 추천좌석 보기 토글을 **OFF**로 설정(또는 기본값 OFF)
3. **예매하기** 클릭
4. 좌석 선택 화면 진입 시 **좌석 맵(맵 모드)** 을 노출
5. 사용자가 좌석 선택 → **Hold 요청**
6. Hold 성공 → 주문서 진입
    - Hold 실패 → 대체 좌석 재시도
### 2.3 좌석 선택 화면에서 토글로 모드 전환(2차 제어)

1. 사용자가 좌석 선택 화면(맵 모드 또는 추천 모드) 진입
2. 사용자가 상단 추천좌석 ON/OFF 토글을 변경한다.
3. 토글 변경 즉시 **하단 ‘블럭 선택 영역’만 리로드**하여 토글 상태에 맞는 UI를 갱신한다.
	- ON: **내블럭 카드 기반 선택 UI** 로드
    - OFF: 좌석 맵 기반 선택 UI 노출
4. 사용자가 **블록 또는 좌석을 선택** → Hold 요청
5. Hold 성공 → 주문서(결제 직전) 진입
    - Hold 실패 → 대체 좌석 재시도

### 2.5 Hold 만료/이탈 시나리오
- Hold 성공 후 타이머가 만료되면 좌석은 자동 해제되며, 사용자에게 만료 안내 후 좌석 선택 화면으로 복귀
- 사용자가 뒤로가기/새로고침 등으로 이탈 후 재진입 시, 정책에 따라 **토글 상태 및 Hold 상태 복원**을 시도
# 3. 기능 명세
---
### 3.1 좌석 선택 화면 공통(상단 토글 + 상태 동기화)
- 화면: 좌석 선택(공통 컨테이너)
- UI 요소
    - 헤더
        - 뒤로가기 버튼
        - 경기정보(경기 일시 / 경기 팀 / 경기 구장)
        - 현재 단계
    - 컨테이너 좌측
        - 경기장 렌더링
    - 컨테이너 우상단
        - 상단 추천좌석 ON/OFF 토글(경기 상세 토글과 동일 의미)
        - 인원(매수) 선택 드롭다운(추천좌석 on일 경우만 노출)
- 동작
    1. 화면 진입 시, 경기 상세에서 설정된 토글 상태를 반영해 초기 모드를 결정한다.
    2. 좌석 선택 화면에서 토글 변경 시, 좌석 선택화면 리로드
    3. 토글 상태는 “단일 상태”로 관리하며, 뒤로가기/재진입 시에도 정책 범위 내에서 일관되게 유지한다.
    4. 헤더 뒤로가기 클릭 시 모달 경고 모달 노출 후 이탈/유지 결정
### 3.2 추천블럭 모드(토글 ON)
- 화면: 내 블럭 선택
- 추천 리스트(UI)
	- 새로고침 아이콘(잔여 좌석/경합 상황 반영하여 재조회)
        - 새로고침 시 추천좌석으로 안내할 수 없는 경우(각 순위별 추천좌석 없는 경우), 모달 노출
            - 좌석 맵 모드로 변경(추천좌석 TOGGLE OFF)
            - 좌석맵에서 토글 비활성화
    - 추천 블럭 카드
		- 블록명 / 구역 정보
		- 잔여 좌석 수 (인원 수 연석 가능 기준)- 기능
		- 선호 점수 기반 정렬 순서 뱃지 (예: #1 ~ #10)
- 기능
	1. **내블럭 목록 조회** (온보딩 선호 점수 기반 정렬 + 잔여 좌석 정보 포함)
	2. 새로고침 클릭 시 잔여 좌석/경합 상황 반영하여 재조회
	3. **블록 카드 선택 시 해당 블록 내 연석 자동배정 후 Hold 요청**
	4. Hold 실패 시 실패 사유 안내 및 **실패 모달** 노출
    5. 토글 OFF로 전환하여 좌석 맵 탐색 가능(전환 시 하단 영역 리로드)
- 추천카드 상태 별 좌석 랜더링
    1. 기본(Default)
        - 좌석맵은 전체 컬러 상태로 표시된다.
        - 내블럭에 포함된 블록은 맵에서 약하게 강조 표시 (미정, 논의 필요)
    2. Hover(카드 호버)
		- 사용자가 내블럭 카드에 마우스 hover 시, 좌석맵에서 **해당 블록 전체 영역**을 강조
    3. Focus(카드 선택)
		- 사용자가 블록 카드를 클릭(선택)하면, 좌석맵 **해당 블록 강조 상태가 고정**
        - 카드도 선택 스타일(배경/테두리 등)로 표시된다.
### 3.3 좌석 맵 모드(토글 OFF)
- 화면: 좌석 맵/좌석 리스트
- 기능
    1. 구역/등급 기반 좌석 조회(맵/리스트)
    2. 경기장 구역 표시
    3. 구역 선택 시 해당 구역 내 좌석 상태 표시
        - AVAILABLE / HELD(타 사용자) / SOLD
    4. 좌석 선택 후 예매하기 or 자동 선택 시 Hold 요청
    5. 토글 ON으로 전환하여 추천 탐색 가능

### 3.5 Hold 생성/만료/해제
- 정의
    - 좌석 확보는 Hold 성공으로 판단
    - 일부만 Hold 성공하는 상태를 허용하지 않는다(사용자 혼란/재고 왜곡 방지)
        - 실패 시 전체 실패로 처리하고 다음 후보를 추천/자동선택 재시도
- 동작
	1. 사용자가 **블록 카드 선택(추천 모드) 또는 좌석 선택(맵 모드)** 후 예매하기 / 자동 선택 시 서버에 Hold 요청
	2. 추천 모드의 경우: 선택된 블록 내에서 인원 수에 맞는 연석을 시스템이 자동 선택하여 Hold 요청
    3. Hold 성공
        - holdId, expiresAt 반환
        - 타이머 표시 및 주문서(결제 직전) 단계로 이동 가능
    4. Hold 실패
		- 사유 코드에 따라 안내 모달 노출
		- 확인하기 클릭 시 모달 닫기
		- 모달 닫힌 후 다른 내블럭 카드 선택 또는 새로고침으로 재시도 가능
### 3.6 하단 CTA(예매하기)
- 화면: 좌석 선택(공통 컨테이너 하단)
- UI 요소 : 예매하기 버튼
- 동작
	- **추천 모드**: Focus된 블록 기준 연석 자동배정 후 Hold 요청
	- **맵 모드**: 현재 선택된 좌석에 대해 Hold 요청
	- 선택(블록 또는 좌석)이 없는 경우: 버튼 비활성
# 4. 정책
---
### 4.1 추천좌석 토글 기본값 정책
- 전체 OFF(기존 흐름 중심)
### 4.2 토글 상태 저장 범위
- 사용자 설정으로 **영구 저장**
### 4.3 경합(동시 선택) 대응 원칙
- 블록 선택은 로컬 표시이며, 확보는 Hold 성공으로 확정
- Hold 실패 시 사용자가 즉시 다음 행동을 할 수 있도록 실패 모달+대체 선택을 제공한다
### 4.4 Hold 정책
- 1~3명: Hold 요청은 **연석 seatIds[]** 단일 묶음으로 전송한다.
- 4명 이상: Hold 요청은 **2인 묶음 단위 seatIds[]를 합산**하여 한 번에 전송한다.
    - 예: 4명(2+2)인 경우 seatIds 4개를 **원자적으로 Hold**해야 한다.
- 원자 Hold 실패 시 처리
    - 일부만 Hold 성공하는 상태를 허용하지 않는다(사용자 혼란/재고 왜곡 방지)
    - 실패 시 전체 실패로 처리하고 다음 후보를 추천/자동선택 재시도
- 1~3인은 반드시 연석
- 4인 이상부터는
    - **4매:** 2+2
    - **5매:** 2+3
    - **6매:** 2+2+2 / 2+4
    - **7매:** 2+3+2 / 4+3
    - **8매:** 2+2+2+2 / 2+2+4 / 4+4
    - **9매:** 2+2+2+3 / 4+2+3
    - **10매:** 2+2+2+2+2 / 2+4+4
### 4.5 동시 Hold 제한(어뷰징 방지)
- 동일 사용자(또는 세션) 동시 Hold 가능 개수 제한: 1개
### 4.6 새로고침/탭 복제/재진입 처리
- idempotencyKey 및 세션 바인딩으로 중복 Hold/중복 주문을 방지
- 재진입 시 토글 상태/hold 상태 복원 범위는 4.2 정책을 따른다

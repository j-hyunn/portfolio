# 1. 배경 및 문제 정의

## 1.1 시장 현황

2025년 KBO는 역대 최다 관중을 기록하며 국내 스포츠 티켓팅 시장의 구조적 성장을 증명했다.

|지표|수치|
|---|---|
|2025 KBO 총 관중 수|**12,312,519명** (2년 연속 최다 갱신)|
|경기당 평균 관중 수|**17,101명**|
|평균 좌석 점유율|**82.9%**|
|연간 티켓 판매 규모 추정|**약 1,290억 원** (평균 티켓가 16,000원 기준)|

성장을 견인한 구조적 요인은 세 가지다.

- **경기력 평준화**: ABS·비디오 판독 확대·피치 클락 도입으로 경기 품질 상승, 9/10 구단 홈 최다 관중 갱신
- **신규 팬층 유입**: 2030 여성 팬층 증가 → 응원 문화·먹거리·포토 스폿 등 경기장 경험 다양화
- **디지털 예매 친화 세대의 주류화**: 스마트폰 기반 예매가 표준화되어 온라인 티켓팅 수요 집중

수요는 충분하다. **문제는 수요 부족이 아니라 수요 분배의 비효율**이다.

## 1.2 핵심 문제

### 문제 1. 핫스팟 좌석 쏠림 (Hotspot Traffic)

사용자들이 동일한 "최선호 구역/열/중앙부"에 동시에 클릭하는 구조에서 좌석 단위 Lock 경합이 발생한다. 결과적으로 특정 좌석에 트래픽이 집중되어 락 실패율 증가, 응답 지연, 서버 과부하로 이어진다.

### 문제 2. 자동배정의 만족도 한계

빠른 확보를 위해 자동배정 방식을 쓰더라도, 사용자는 "어디에 배정될지 모른다"는 불확실성을 감수해야 한다. 확보 후에야 위치를 파악할 수 있어 관람 경험 저하로 이어진다.

### 문제 3. 좌석 빈틈 — 연석 확보 실패

직접 좌석 선택 시 빠른 확보가 우선이 되면서 아무 좌석이나 개별 선택하게 되고, 결과적으로 좌석이 띄엄띄엄 분산되어 동행자와 연석 확보가 어려워진다.

### 문제 4. 매크로·봇으로 인한 정상 사용자 피해

국내 설문 데이터(마크로밀엠브레인, 만 19~39세 KBO 팬 대상)에 따르면 응답자의 **72.5%가 2차 티켓 구매를 고려**했으며, 암표 횡행의 원인으로 **"매크로/봇 차단 기술 부족"이 26.5%로 1위**를 차지했다. 봇이 핫스팟 좌석을 선점할수록 정상 사용자의 실패율은 구조적으로 높아진다.

### 문제 5. 운영 비용 비효율

피크 트래픽 전체를 인프라 증설로 대응하는 방식은 비용 비효율적이며, 좌석 선택 단계의 락 경합 병목은 서버 증설만으로는 해소되지 않는다.

---

## 1.3 사업적 기회

연간 1,290억 원 규모의 KBO 티켓팅 시장에서 수요 분배 비효율을 구조적으로 개선하면 다음 효과가 기대된다.

- **좌석 확보 성공률 상승** → 사용자 만족 및 재방문 증가
- **서버·락 경합 감소** → 성능 개선 및 인프라 비용 절감
- **봇 효율 저하** → VQA 인증 + 분산 추천으로 방어 비용 대비 효과 증대
- **2차 티켓 시장 수요 흡수** → 1차 정상 예매 성공률이 높아지면 암표 수요 자체가 감소

# 2. 제품 비전 및 포지셔닝

## 2.1 비전

> 좌석 선택에서 발생하는 경쟁을 '한 점의 전쟁'에서 '분산된 공정 경쟁'으로 바꾸는 티켓팅 플랫폼

## 2.2 핵심 가치 제안

- **팬(B2C)**: 원하는 구역에서 연석을 더 빠르게, 더 높은 확률로 확보한다. 자동배정 수준의 편의성 + 내가 원하는 구역이라는 만족도.
- **구단(B2B)**: 빅매치에서도 서버 장애·CS 민원·환불 비용이 줄고, 경기별 예매 데이터 인사이트를 확보한다.
- **운영사**: 트래픽이 안정화되고 서버 비용이 낮아지며, 정상 예매 생태계가 복원된다.
- **KBO(시장)**: 리그 신뢰도가 높아지고, 신규 팬층의 이탈이 줄어들며, 팬 경험이 표준화된다.

## 2.3 차별화 포인트

|구분|경쟁 접근|Playball 접근|
|---|---|---|
|트래픽 대응|인프라 증설·대기열·랜덤 배정으로 **트래픽을 견딤**|좌석 선택 수요 분포 자체를 재설계하여 **병목을 구조적으로 줄임**|
|좌석 배정|완전 자동(어디인지 모름) vs 완전 수동(빠른 경합)|**온보딩 선호 기반 블록 추천 + 연석 자동배정** — 원하는 구역 내 빠른 확보|
|봇 방어|IP 차단, 속도 제한 등 수동적 방어|**VQA 게임 인증** — 야구 테마 미니게임으로 사용자 부담은 낮추고 봇 효율은 낮춤|

# 3. 타겟 고객

## 3.1 1차 타겟

- **B2C**: 빅매치·플레이오프·개막전 등 고수요 경기 구매자 — 특히 동행자가 있어 **연석 확보가 필수**인 사용자
- **B2B**: 프로 스포츠 구단·경기 운영사·티켓 대행사

## 3.2 핵심 페르소나

**페르소나 A — "배정받은 자리가 어딘지 알고 싶어"**

- 32세 남성, K구단 팬
- 자동배정은 빠르지만 어디 앉을지 모른다는 불안감
- 직접 좌석 선택은 느리고 경합에서 밀린다
- **핵심 니즈**: 빠르면서도 원하는 구역에 배정받는 경험

**페르소나 B — "친구들이랑 꼭 붙어서 보고 싶어"**

- 28세 여성, L구단 팬
- 직접 선택 시 띄엄띄엄 남은 좌석 때문에 연석 확보가 번번이 실패
- **핵심 니즈**: 연석 확보가 최우선 — 구역은 대략 맞으면 OK

## 3.3 포지셔닝

> "스포츠 티켓팅에서 발생하는 좌석 핫스팟 전쟁을 **추천 기반 분산**으로 완화해, **연석·선호 구역 확보 성공률을 높이는** KBO 티켓팅 플랫폼"

# 4. 핵심 사용자 시나리오

## 4.1 As-Is (현재 문제 흐름)

```
좌석맵 진입
    → 모두가 동일 핫스팟 확대
    → 특정 좌석 클릭 폭주
    → 락 실패 반복
    → 이탈·불만·2차 시장 유입
```

자동배정 대안은 존재하지만, 배정 위치를 사전에 알 수 없어 만족도가 낮다.  
직접 선택은 경합에서 밀리고, 남은 좌석이 흩어져 연석 확보에 실패한다.

## 4.2 To-Be (Playball 목표 흐름)

```
온보딩 (최초 1회)
    → 선호 블록 최대 10개 직접 선택
    → 관람 구역·응원 구단·환경 선호 수집

예매 진입
    → 경기 상세에서 인원 수 설정 + 추천 토글 ON
    → 대기열 통과 → VQA 인증 (야구공 캐치, 1회)

좌석 선택 (추천 모드)
    → 내블럭 목록 노출 (연석 가능 수 1순위 + 선호 점수 2순위 정렬)
    → 블록 카드 선택 → 연석 자동배정 → Hold

결과
    → 동일 인프라 대비 Hold 성공률 상승
    → 좌석 단위 경합 구조적 제거
    → 재시도 횟수·이탈 감소
```

# 5. 제품 요구사항

## 5.1 기능 요구사항

### A. 온보딩 — 선호 데이터 수집

- 신규 가입 직후 **1회 필수 완료** (스킵 불가)
- 수집 데이터
    - **내블럭 선택**: 경기장 블록 맵에서 직접 탭, 최대 10개
    - **필수 선호**: 관람 구역(zone_area), 응원 구단(cheering_team), 응원석 거리 선호
    - **선택 선호**: 좌석 타입·관람 환경·분위기·시야 민감도·가격 민감도
- 마이페이지에서 언제든 수정 가능 (기 생성 주문·Hold에는 미반영)

### B. 분산 추천 — 핫스팟 완화

- **추천 단위는 블록(Block)**, 좌석 단위 추천 금지 (Lock 경합 집중 방지)
- 내블럭(최대 10개) 중 **연석 가능 블록만 후보**로 노출
- **정렬 우선순위**
    1. 연석 확보 가능 수 (높을수록 상위)
    2. 선호도 점수 (연석 수 차이가 작을 때만 적용, 최대 70점)
- 혼잡도는 **블록 단위 집계** 사용 (피크 시 좌석 단위 조회 금지)
- 추천 이유는 "연석 가능", "경쟁 낮음", "선호 구역" 등 **2~3개 라벨**로만 표시

### C. 연석 자동배정

- 블록 카드 선택 시 시스템이 인원 수에 맞는 연석을 자동 선택하여 Hold 요청
- 1~3인: 동일 행 연석
- 4인 이상: 2인 묶음 분할 (4→2+2, 6→2+2+2 등)
- 인근 좌석 허용 토글 ON 시: 1열 이내 인접 행 분산 확보 허용

### D. Hold 성공률 최적화

- Hold 실패 시 즉시 **다음 내블럭 카드 강조** + 최소 안내 ("해당 블록 경쟁이 증가했습니다")
- 일부 Hold 성공 상태 불허 — 전체 성공 또는 전체 실패로만 처리 (재고 왜곡 방지)
- 동일 사용자 동시 Hold 1건 제한 (어뷰징 방지)

### E. 대기열 — 공정한 순서 보장

- 예매 오픈 시 CCU·TPS 임계치 초과 시 즉시 활성화
- 초당 최대 100명 통과 (promotion-batch-size 기준)
- 대기 순위에 따른 차등 폴링 주기 (상위 100명: 1.5초 / 101~1000명: 3초 / 1001위~: 5초)
- 통과 준비 완료(READY) 후 **60초 이내 미진입 시 순번 초기화**

### F. VQA 인증 — 봇 방어

- 발동 시점: 대기열 통과 직후 **1회 고정** (예매 중간 추가 인증 없음)
- 야구공 캐치 미니게임 — 위치 + 타이밍 두 조건 동시 충족 시 통과
- 판정은 서버에서 수행 (클라이언트에 정답 미노출)
- 재시도: 1회 실패 즉시 재도전, 2회 실패 2.5초 대기, 60초 내 2회 초과 시 30초 일시 정지
- 경기 상세 하단에 **사전 체험(튜토리얼) 상시 노출** (최대 3회, 실제 예매 무관)

### G. 주문·결제

- Hold 성공 후 주문서 진입 → 권종 분해 → 결제 수단 선택
- 결제 수단: 카카오페이, 토스페이, 무통장 입금
- 멱등성(idempotencyKey) 처리 필수 — 중복 주문 방지
- 취소·환불: 경기 7일 전 이상 무수수료, 6~1일 전 10% 수수료, 당일 취소 불가

## 5.2 UX/정책 요구사항

- 추천은 **보조 기능** — 맵 모드 전환은 언제든 가능 (토글 ON/OFF)
- 추천 알고리즘 내부 점수·순위 수치는 사용자에게 노출하지 않음
- 공정성: 동일 조건 사용자 간 블록 확보는 선착순, 플랫폼이 임의로 특정 사용자를 우대하지 않음
- 비회원은 탐색(구단·경기 정보 조회)만 가능, 예매 진입 시 로그인 요구
- 취소 기한·수수료는 주문서·결제 화면·완료 화면에 명시적으로 고지

---

## 5.3 추천 알고리즘 요구

|요구 특성|기준|
|---|---|
|실시간성·경량성|폭주 환경에서 추천이 병목이 되지 않을 것|
|설명 가능성|최소한의 "왜 이 후보인가" 라벨 제공 가능|
|분산 최적화 내장|후보 다양화·노출 균형을 기본 제약으로 포함|
|제약 처리|연석·구역 제외·홈/원정 응원석 룰 반영|

산출 형태: 사전 계산된 후보군 + 혼잡도 기반 재정렬 + 노출 균형 로직 조합 권장.  
폭주 상황에서는 좌석 추천이 아닌 구역/블록 추천으로 자동 전환 가능해야 함.

# 6. 비기능 요구사항(NFR) 및 성능 목표

## 6.1 성능 목표 (3,000석 기준 Staging 환경)

|지표|목표|
|---|---|
|Hold 성공률 (추천 ON)|**70% 이상**|
|Hold 응답시간 p95|**3초 이내**|
|주문 생성 응답시간 p95|**3초 이내**|

## 6.2 안정성 원칙

- **Graceful Degradation 필수**: 추천 레이턴시 증가가 오히려 성공률 악화로 이어지므로, 장애 시 추천 품질을 낮추더라도 시스템을 보호
- 추천 중단 시에도 맵 모드(기본 좌석맵)는 반드시 정상 동작
- 인증 서버 장애 시 VQA 실패 횟수 누적 금지, 관리자 판단 하에 인증 차단 해제 가능

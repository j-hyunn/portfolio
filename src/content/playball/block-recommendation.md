# 1. 선호 데이터 점수화 방식 (랭크 → 가중치 변환)
---
### 1.1 랭크 가중치 테이블
각 질문별로 사용자가 선택한 옵션에 랭크 가중치를 부여합니다.
- 1순위: 1.00 / 2순위: 0.60 / 3순위: 0.30 / 미선택: 0.00

### 1.2 질문별 중요도
> 합계는 1.0 근처로 맞추되, 실제 구현은 **정규화** 해서 사용

좌석 추천에 미치는 영향력을 질문별로 다르게 둡니다(필수 질문 > 선택 질문).
- Q1(어디): w=0.24
- Q2(높이): w=0.18
- Q3(구역 위치): w=0.18
- Q4(통로/중앙): w=0.08
- Q5(그늘): w=0.07
- Q6(응원/조용): w=0.10
- Q7(시야방해 민감): w=0.10
- Q8(가격대): w=0.05 _(단, “동일 조건일 때만” 정책이면 tie-breaker로 내려도 됨)

# 2. 블록 속성 정의 및 매핑
---
> ⚠️ 기존 "좌석 속성" → **"블록 속성"** 으로 변경. 추천 및 점수 계산의 단위는 좌석이 아닌 블록임.

### 2.1 블록 속성(필수)
- `block_id`: 블록 고유 식별자
- `zone_area`: {내야/외야, 1루/3루/중앙, 외야 좌/중/우}
- `zone_position`: {중앙쪽/중간/코너(파울라인)}
- `height_band`: {하단/중단/상단}
- `sun_exposure`: {그늘/혼합/직사} (경기 시간·구장 방향 기반 사전/예측값)
- `atmosphere`: {응원존 근접/일반/조용존} (구역 정책 테이블)
- `obstruction`: {안전망/난간/기둥/없음} 및 강도(없음~심함)
- `price_range`: 블록 내 좌석 가격 범위(min/max)
- `remaining_seats`: 현재 잔여 좌석 수
- `adjacency_ok(n)`: 인원 n명 기준 연석 가능 여부
- `congestion_level`: 현재 경쟁 강도 집계값 (블록 단위)
- `is_my_block`: 사용자 온보딩 선택 블록 여부 (true/false)

> ※ 기존 `seat_type`(통로/중앙)은 **연석 자동배정 시 내부 로직에서만 참조**하며, 블록 점수 계산에서는 제외

### 2.2 온보딩 답변 → 블록 속성 매핑 규칙
- **Q1(어디에서)** → `zone_area` 매칭 점수
    - 예: 사용자가 1루 내야 1순위면, 1루 내야 구역은 높은 점수
- **Q3(구역 위치)** → `zone_position` 매칭 점수
    - 중앙쪽 선호: 홈플레이트/센터라인에 가까운 블록 우대
    - 코너 선호: 파울라인·코너 블록 우대
- **Q2(높이)** → `height_band` 매칭 점수
    - 하단 선호: 앞쪽/낮은 층 우대(구장별 ‘열/단’ 기준 테이블 필요)
- **~~Q4(통로/중앙)** → `seat_type` 매칭 점수~~
    - ~~통로 선호: aisle 좌석에 플러스~~
    - ~~중앙 선호: 블록 중앙열/중앙좌석 플러스~~
- **Q5(그늘)** → `sun_exposure` 매칭 점수
    - 그늘 선호: 그늘 확률 높은 구역(또는 지붕/방향) 우대
- **Q6(응원/조용)** → `atmosphere` 매칭 점수
    - 열정적 응원: 응원존 근접 구역 우대
    - 조용한 관람: 조용존/패밀리존 우대
- **Q7(시야 방해 민감)** → `obstruction` 패널티
    - 안전망 민감: 안전망 존재 구역에 감점(민감도가 클수록 큰 감점)
    - 난간/기둥 민감: 해당 obstruction 감점
    - 둔감: 감점 최소
- **Q8(가격대)** → price 타 브레이커 또는 제한적 반영
    - “동일 조건” 정책이면: **최종 점수 상위 후보가 동점/근소 차일 때만** 가격 적합도로 정렬

# 3. 최종 점수 계산
---
### 3.1 매칭 점수 산출
각 질문마다 블록이 "해당 옵션"에 얼마나 부합하는지 match()로 0~1을 산출한다.

### 3.2 랭크 반영
```
PrefScore_Qi(block) = max_over_selected_options( rank_weight(option) * match(block, option) )
```

### 3.3 최종 점수
```
BlockScore = normalize( Σ (QuestionWeight_i * PrefScore_Qi) - ObstructionPenalty , 0..100 )
```

**정렬 우선순위**
1. `is_my_block = true` 블록만 후보
2. `adjacency_ok(partySize) = true` 블록 우선 (연석 가능 여부)
3. BlockScore 내림차순 정렬
4. 동점 시 `remaining_seats` 많은 순 → `congestion_level` 낮은 순

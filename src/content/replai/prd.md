## 1. 배경 및 문제 정의

### 1.1 문제

취준생은 면접을 준비할 때 두 가지 지점에서 막힌다.

1. **이력서** — 회사마다 요구사항이 다른데, 지원할 때마다 이력서를 다시 다듬을 기준이 없다. 내 경험 중 무엇을 강조하고 무엇을 덜어낼지 판단할 근거가 없다.
2. **면접** — 모의면접을 진행할 환경 자체가 없다. 면접 스터디는 일정 조율이 어렵고 피드백 품질도 일정하지 않다. 유료 컨설팅은 비용 부담이 크다.

> **핵심 문제: 사람 의존 없이, 언제 어디서든, 내 이력을 아는 상대와 지원 준비를 할 수 있는 환경이 없다.**

### 1.2 솔루션

Replai는 **하나의 마스터 이력서**를 기준으로 두 가지를 제공한다.

- **JD 맞춤 제출용 이력서 생성** — 마스터 이력서에서 해당 JD에 필요한 경험만 골라내고, 개조식으로 재작성한다.
- **나를 아는 AI 면접관과의 모의면접** — 제출용 이력서·마스터 이력서·업로드 문서를 컨텍스트로 읽은 면접관이 맥락 있는 질문을 던진다.

실제 면접은 **직무(역량) 인터뷰 + 컬쳐핏 인터뷰** 두 트랙으로 나뉜다. MVP는 직무 인터뷰만 다룬다.

## 2. 목표

### 2.1 제품 목표

- 흩어져 있는 경력·프로젝트 이력을 한 곳에 정리하고, 지원처마다 재사용할 수 있게 한다
- JD와 내 이력에 기반한 맥락 있는 질문으로 실질적인 면접 연습 효과를 만든다
- 면접 후 구체적인 피드백으로 개선 방향을 제시한다

### 2.2 MVP 핵심 지표 (KPI)

MVP 기간을 **론칭 후 4주**로 정의하며, 아래 수치를 성공 기준으로 삼는다.

|지표|측정 방법|목표 수치|경고 수치|
|---|---|---|---|
|**면접 완주율**|면접 시작 이벤트 대비 종료 이벤트 발생 비율|≥ 65%|< 45%|
|**피드백 열람률**|리포트 화면 진입 후 30초 이상 체류한 비율|≥ 75%|< 50%|
|**7일 내 재방문률**|첫 면접 완료 후 7일 이내 면접을 1회 이상 재진행한 비율|≥ 30%|< 15%|

> **측정 수단:** Google Analytics 연동됨(`@next/third-parties`, `G-NLL8P9G6YE`). 세션·리포트 원본 데이터는 Supabase 직접 쿼리 병행.
> **미정:** 마스터 이력서 축의 KPI(작성 완료율, 제출용 이력서 생성 후 면접 전환율)는 아직 정의되지 않았다 — §9 참조.

**경고 수치 도달 시 액션:**

- 완주율 < 45% → 면접 진행 중 이탈 지점 분석, 면접 시간 설정 기본값 검토
- 피드백 열람률 < 50% → 리포트 화면 첫 인상 UX 개선 우선 검토
- 재방문률 < 15% → 첫 면접 리포트 품질 집중 개선 (평가 프롬프트 튜닝)

## 3. 타겟 유저

### 3.1 Primary

**IT 직군 경력직 이직 준비자**

- 직군: 개발자, PM, 디자이너, AI 엔지니어, 인프라 엔지니어
- 실전 면접 준비를 위한 맞춤형 모의면접이 필요한 사람

### 3.2 Secondary

**IT 직군 신입 취준생**

- 면접 경험이 부족하고 피드백 받을 곳이 없는 사람
- 이력서 작성 자체가 처음이라 무엇을 어떻게 써야 할지 모르는 사람

### 3.3 트리거 시점

**이력서 작성 시점 ~ 면접 전날**

> v3.5까지는 "서류 합격 직후 ~ 면접 전날"이었다. 마스터 이력서·제출용 이력서 생성이 추가되면서 **서류 지원 전 단계로 진입 시점이 앞당겨졌다.**

## 4. 범위 (Scope)

### 4.1 MVP In Scope

**[인증]**

- Google 소셜 로그인

**[온보딩]**

- 최초 로그인 시 2단계 위저드 플로우 자동 진입 (`/onboarding`)
- Step 1 — 내 소개: 직군·연차 필수 입력, 기술 스택·스킬 선택 입력
- Step 2 — 문서 업로드: 이력서·포트폴리오 (전부 선택, 건너뛰기 가능)
- 온보딩 완료 기준: `job_category !== null` (재로그인 시 온보딩 반복 없음)
- 완료 후 `/interview`로 이동

**[마스터 이력서]** ← v4.0

- 7개 섹션 구조화 입력 — 기본 정보 / 경력 / 프로젝트 / Hard·Soft Skills / 학력 / 수상·자격증·활동 / 자기소개 소재 메모
- 유저당 1개 (`master_resumes` UNIQUE user_id)
- 마크다운 에디터(tiptap) 기반 서술형 필드
- 섹션별 작성 완료 여부 표시

**[제출용 이력서 생성]** ← v4.0

- 회사명 · 포지션 · JD 입력 → 4단계 AI 파이프라인으로 JD 맞춤 이력서 생성
- 생성 결과: 구조화 이력서(`content_json`) + JD 분석(`analysis_json`)
- 표준 이력서 레이아웃으로 렌더 (경력 하위에 해당 회사 프로젝트 통합)
- 생성한 제출용 이력서로 바로 면접 준비 진입 가능
- 개수 제한 없음

**[문서 관리]**

- 이력서/경력기술서, 포트폴리오 PDF 업로드 후 계정에 저장
- 언제든 삭제/재업로드 가능 (삭제 시 DB + Storage 완전 삭제)
- 업로드 응답 ~5초 — AI 정밀 분석은 백그라운드 진행
- 문서 카드 분석 상태 표시 — `normalize_status` 기반 pending / done / failed 배지 + 재시도 버튼
- 인터뷰 시작 시 분석 완료 보장 — `parsed_text`만으로 인터뷰 진행 금지

**[입력]**

- JD: 텍스트 직접 입력
- 이력서/경력기술서: **면접 시작 필수** (PDF)
- 포트폴리오: 선택 (PDF)

**[면접 설정]**

- 면접 제목: 직접 입력 (히스토리 구분용)
- 제출용 이력서 선택: 선택 (선택 시 JD 자동 채움)
- 면접 시간: 10분(임시) / 30분 / 60분 / 90분 선택 (기본값 없음, 반드시 선택)
- 면접관 페르소나: 경험 탐색형 / 심층 압박형 / 기술 검증형 (3종 선택)

**[시뮬레이션]**

- AI 면접관과 텍스트 기반 대화형 직무 인터뷰
- AI 면접관 음성 출력 (TTS, 기본값 켜짐 / 토글 가능)
- 유저 마이크 음성 입력 (STT → 텍스트 변환 후 답변으로 전송)
- 유저 답변에 따른 꼬리질문 (explorer 최대 2단계, pressure/technical 최대 4단계)
- 힌트 버튼 온디맨드 (이력서 기반 AI 실시간 모범 답안 생성)
- 질문 건너뛰기
- 중간 이탈 시 이어하기 가능
- 인터뷰 시작 가드 — 시작 버튼 클릭 시 선택된 문서가 분석 미완료면 "AI 분석 마무리 중..." 단계 UI 후 진입

**[환경설정]**

- 마이크 / 스피커 장치 선택
- 마이크 음량 / 스피커 음량 조절
- 마이크 테스트 (실시간 레벨 미터)

**[AI 모델 설정]**

- 사용자 Gemini API 키 등록 시 상위 모델 선택 가능
- Settings 페이지에서 API 키 등록/삭제, 모델 변경, 표시명 변경, 계정 삭제

**[리포트]**

**[히스토리]**

## 5. 유저 플로우

### 5.1 첫 방문자 플로우

```
[STEP 1] 랜딩 및 로그인
  └─ Google 소셜 로그인
  └─ 최초 로그인 시 → 온보딩 위저드 진입 (/onboarding)
  └─ 재방문자 → /interview 바로 이동

[STEP 2] 온보딩 — 내 소개 (신규 사용자만)
  └─ 직군·연차 선택 (필수), 기술 스택·스킬 입력 (선택)

[STEP 3] 온보딩 — 문서 업로드 (신규 사용자만)
  └─ 이력서·포트폴리오 업로드 (선택)
  └─ "완료" 또는 "건너뛰기" → /interview
```

### 5.2 이력서 플로우 (v4.0 신설)

```
[서류 관리 /resume]
  ├─ 마스터 이력서
  │    └─ 없으면 "생성하기" → /resume/master
  │         └─ 7개 섹션 작성 → 저장
  │
  ├─ 제출용 이력서
  │    └─ "생성하기" (마스터 이력서 없으면 비활성)
  │         └─ 회사명 · 포지션 · JD 입력
  │         └─ 4단계 AI 파이프라인 (§6.13)
  │         └─ 완료 → /resume/submitted/[id] 뷰어
  │              └─ "면접 준비" → /interview?submittedResumeId=...
  │
  └─ 이력서 / 포트폴리오 파일 업로드 (면접 시작에 필요)
```

### 5.3 면접 플로우

```
[STEP 1] 면접 설정 (/interview에서 다이얼로그)
  └─ 면접 제목 입력
  └─ 제출용 이력서 선택 (선택 — 선택 시 JD 자동 채움)
  └─ JD 입력
  └─ 이력서·포트폴리오 선택 (이력서 1개 이상 필수)
  └─ 면접 시간 선택
  └─ 면접관 페르소나 선택
  └─ "면접 시작하기"
  └─ ensureNormalizedAction(선택된 문서)
       ├─ 모두 done → 즉시 STEP 2
       ├─ pending/failed 있음 → "AI 분석 마무리 중..." 모달 (최대 ~1분/문서)
       │     ├─ 성공 → STEP 2
       │     └─ 실패 → 에러 토스트 + 다이얼로그 유지
       └─ 통과 후 createInterviewSessionAction

[STEP 2] AI 컨텍스트 분석 (약 10~20초)
  └─ 컨텍스트 우선순위: 제출용 이력서 > 마스터 이력서 > 업로드 문서
  └─ 분석 완료 → STEP 3으로 자동 전환

[STEP 3] 모의면접 시뮬레이션
  └─ AI 면접관 인트로 멘트 (TTS 음성 출력)
  └─ 질문 → 유저 답변 → 꼬리질문 반복
  └─ 힌트 버튼 / 건너뛰기 온디맨드
  └─ 시간 종료 또는 유저 직접 종료

[STEP 4] 리포트
  └─ 평가 중 로딩 표시
  └─ 총점 및 총평, 강점/개선점 + 키워드
  └─ 답변별 평가 + 모범 답안
```

### 5.4 재방문자 플로우

```
[로그인]
  └─ /interview: 최근 면접 기록 + "새 면접 시작하기" 버튼
  └─ 미완료 세션 있을 경우 → 목록에서 "진행 중" 상태로 표시

[이어하기]
  └─ 해당 세션 진입 → remaining_seconds로 타이머 복원
  └─ 대화 이력 복원 후 재개
```

### 5.5 빈 상태 (Empty State) 처리

|상황|표시 내용|
|---|---|
|마스터 이력서 없음|"아직 마스터 이력서가 없습니다" + 생성하기 버튼|
|제출용 이력서 없음|"아직 제출용 이력서가 없습니다"|

|히스토리 없음|"아직 면접 기록이 없어요"|

|문서 분석 실패|"분석 실패" 배지 + 재시도 버튼|

**문서 카드 상태 표시:**

|상태|배지|UX|
|---|---|---|
|`pending`|"AI 분석 중" (회색 + spinner)|`/resume`에서 5초마다 폴링해 자동 갱신|

**엣지 케이스:**

|상황|처리 방식|
|---|---|
|텍스트 0자 PDF (스캔본·이미지 기반)|**업로드 단계에서 명시적 거부** + Storage cleanup. "PDF에서 텍스트를 추출할 수 없습니다. 스캔본/이미지 PDF는 지원하지 않습니다"|
|파일 크기 초과|업로드 전 클라이언트에서 차단, 용량 초과 안내|

|항목|상세|

|면접 제목|직접 입력 필수 (히스토리에서 구분용)|

### 6.4 면접관 페르소나

|페르소나 (코드값)|이름|분위기|꼬리질문 상한|
|---|---|---|---|
|`explorer`|경험 탐색형|편안하고 대화적|최대 2단계|
|`pressure`|심층 압박형|날카롭고 도전적|최대 4단계|
|`technical`|기술 검증형|설계·CS·성능 why/how 집중 검증|최대 4단계|

**커스텀 지침:**

- 유저가 각 페르소나에 추가 지침을 직접 작성할 수 있음
- 작성 위치: 사이드바 > 면접 > 면접관 페르소나
- AI 면접관은 기본 지침 + 유저 커스텀 지침을 합산해 면접 진행
- 커스텀 지침 미작성 시 기본 지침만 적용

### 6.5 힌트 기능

- 노출 방식: "힌트 보기" 버튼 클릭 시 AI가 실시간으로 이력서 기반 모범 답안 생성

### 6.8 이어하기

- 이탈 시 `handleExit()` 명시 호출로 남은 시간(`remaining_seconds`) 저장
- 재접속 시 `in_progress` 세션을 히스토리에서 "진행 중"으로 표시 → 진입하면 남은 시간·대화 이력 복원
- ADK 세션은 콜드 스타트 시 `ensureAdkSession()`이 최근 30개 메시지를 재생해 복구

> **유효 기간 없음.** v3.5 문서에 기재됐던 "24시간 경과 시 abandoned 처리"는 구현되지 않았다 — §9 참조.

### 6.9 리포트

**답변별 평가 항목:**

|평가 축|설명|배점|
|---|---|---|
|논리성|두괄식 구성, STAR 구조 여부, 일관성|100점|
|구체성|수치/사례 활용 여부, 추상 표현 최소화|100점|
|직무 적합성|JD 요구 역량과의 연관성, 키워드 매칭|100점|

**서버 결정 사항 (LLM 계산 불신):**

- `average` = `Math.round((logic + specificity + job_fit) / 3)` — 서버 재산출
- `total_score` = skipped·failed 제외 답변의 평균 — 서버 산술
- 힌트 사용 답변은 각 항목 30점으로 clip 후 average 재계산

**답변 상태 4종 (서버 계산):**

|상태|의미|점수 처리|
|---|---|---|
|`answered`|정상 평가 완료|서버 산술 average|
|`hint_shown`|모범 답안 참조 후 평가|각 항목 최대 30점 캡|
|`skipped`|질문 건너뜀|0점, total_score 계산 제외. 학습용 모범 답안은 생성됨|
|`failed`|평가 호출 3회 실패|0점, total_score 계산 제외|

> **주의 — 리포트 화면은 이 상태를 표시하지 않는다.** 서버는 `status`를 계산해 `report_json`에 저장하지만, 클라이언트 타입(`AnswerReport`)에 `status` 필드가 없고 `ReportView`도 읽지 않는다. 따라서 **힌트 사용·건너뜀·평가 실패 답변이 화면에서 정상 답변과 구분되지 않는다.** 점수만 낮게 표시된다 — §9 참조.

**리포트 구성 (실제 렌더 항목):**

- 총점 + 3축 평균 점수 바
- 총평 — 강점 / 개선점 + 각각의 키워드 칩 (`strength_keywords` / `improvement_keywords`)
- 문항별 패널 — 질문 의도 칩, 본 질문·꼬리질문 대화, 3축 점수, 피드백, 모범 답안

**엣지 케이스:**

|상황|처리 방식|
|---|---|
|질문 단건 평가 3회 실패|해당 답변만 `failed`로 처리하고 리포트 생성은 계속 진행|
|종합 평가(요약) 3회 실패|500 반환 + 재생성 유도 (리포트 미생성)|
|평가 전체 타임아웃|호출별 최대 45초, 전체 예산 초과 시 남은 재시도 중단|
|리포트 저장 실패|500 반환 + "리포트 생성을 다시 시도해주세요"|

### 6.10 히스토리

- 최근 10개 세션 조회 (`limit(10)`)
- 이어하기 중인 세션은 "진행 중" 상태로 표시
- 세션 직접 삭제 가능 (`deleteInterviewSessionsAction`)

> **자동 삭제 없음.** 11번째 세션도 정상 생성되며, 오래된 세션은 조회 목록에서 밀려날 뿐 DB에 남는다. v3.5 문서의 "10회 초과 시 자동으로 가장 오래된 기록 삭제"는 구현되지 않았다 — §9 참조.

### 6.11 AI 모델 설정 (BYOK)

사용자가 자신의 Gemini API 키를 등록하면 기본 모델보다 성능이 높은 상위 모델로 면접을 진행할 수 있다.

**지원 모델:**

|모델|제공 방식|특징|
|---|---|---|
|gemini-2.5-flash|서버 기본 키 (무료)|기본값. 별도 설정 불필요|
|gemini-2.5-pro|사용자 API 키 필요|향상된 분석·평가 품질|
|gemini-3.1-pro-preview|사용자 API 키 필요|최고 성능|

**Settings 페이지 구성:**

- 계정 정보 / 표시명 변경
- Gemini API 키 입력·저장·삭제 (저장 시 AES-256-GCM 암호화)
- 모델 선택 드롭다운
- 계정 삭제 (Danger Zone)
- 안내 문구: API 키는 암호화 후 저장되며 서버에서만 복호화. 음성 기능(TTS/STT)과 문서 분석(normalize)은 항상 기본 키 사용

**엣지 케이스:**

|상황|처리 방식|
|---|---|
|유효하지 않은 API 키 입력|저장 전 `/v1beta/models` 호출로 검증 → 실패 시 저장 안 됨|
|API 키 삭제|기본 모델(gemini-2.5-flash)로 자동 복귀|
|TTS/STT/Normalize|키 설정과 무관하게 항상 서버 기본 키 사용|

|기본 정보|이름, 이메일, 연락처, 웹사이트, 소개|
|경력|회사명, 직급/직책, 입사일·퇴사일(재직 중 체크), 업무 내용, 퇴사 사유|
|프로젝트|프로젝트명, 회사명, 기간, 프로젝트 내용, 의사결정 및 협업, 성과, 기여도, 사용 기술|
|Hard / Soft Skills|하드 스킬 목록, 소프트 스킬 목록|
|학력|학교, 전공, 학위(고등학교~박사), 입학·졸업일, 입학/편입, 졸업/중퇴/재학중|
|수상 / 자격증 / 활동|제목, 발급처, 취득일, 설명|
|자기소개 소재 메모|면접 대비용 메모. **이력서 출력물에는 포함되지 않음**|

**동작:**

- 섹션별로 모든 항목이 채워졌는지 표시 (작성 완료 여부)
- 저장 시 `/resume`, `/resume/master` 재검증
- 면접 시작 시, 경력 또는 프로젝트가 1개 이상 있으면 마크다운으로 직렬화되어 AI 컨텍스트에 주입

### 6.13 제출용 이력서 생성 — v4.0

마스터 이력서를 기반으로 특정 JD에 맞춘 이력서를 AI가 생성한다.

**입력:**

|항목|필수|예시|
|---|---|---|
|회사명|필수|카카오|
|포지션|필수|백엔드 개발자|
|채용 공고 (JD)|필수|공고 전문 붙여넣기|

**4단계 파이프라인:**

```
1단계  JD 분석 + 전략 수립       → JdAnalysis
2단계  마스터 이력서 필터링       → FilteredContent  (JD에 필요한 항목만 선별)
3단계  개조식 재작성             → RewrittenContent (제출용 문장으로 변환)
4단계  분석 생성                 → keyword_mapping / highlights / missing_items
```

- 각 단계 실패 시 최대 3회 재시도 (1초 × 시도 횟수 백오프)
- 3회 실패 시 단계별 에러 메시지와 함께 502 반환 (예: "JD 분석에 실패했습니다", "문장 변환에 실패했습니다")
- 마스터 이력서가 없으면 422 + "마스터 이력서를 먼저 작성해주세요"
- 사용자 BYOK 키/모델 적용

**출력 및 표시:**

- `content_json` — 구조화 이력서 (마스터 이력서와 동일 스키마 + JD 맞춤 요약)
- `analysis_json` — 키워드 매핑 / 강조 포인트 / 부족한 항목
- 뷰어(`/resume/submitted/[id]`)는 표준 이력서 레이아웃으로 렌더 — **경력 하위에 같은 회사의 프로젝트를 통합**하고, 매칭되지 않는 프로젝트는 "기타 프로젝트"로 분리
- 카드에서 "면접 준비" 클릭 시 해당 이력서를 고정한 채 면접 설정 진입

**면접 컨텍스트 연동:**

- 세션에 `submitted_resume_id` 저장
- AI 컨텍스트 우선순위: **제출용 이력서 > 마스터 이력서 > 업로드 문서**
- `content_json`을 마크다운으로 직렬화해 주입 (레거시 행은 `content_md` 폴백)

**엣지 케이스:**

|상황|처리 방식|
|---|---|
|마스터 이력서 없음|생성 버튼 비활성 + 서버에서도 422 차단|
|생성 중 이탈|진행 중 요청은 유지되나 결과 화면 미표시 — 목록에서 확인|
|JD 맞춤 요약 위치 불일치|LLM 출력이 최상위 `summary` 대신 `basics.summary`에 넣는 경우가 있어, 뷰어·직렬화 모두 최상위 → basics 순으로 폴백|
|생성 소요 시간|4단계 순차 호출로 수십 초 소요. `maxDuration = 300` 설정 — 문서가 전제해온 "무료 티어 60초"와 불일치 (§7.1)|

### 7.1 기술적 리스크 및 대응

|리스크|내용|대응 방안|
|---|---|---|
|**API Route maxDuration 300**|`/api/interview`와 `/api/resume/generate` 모두 `maxDuration = 300`. 문서 전반이 전제해온 "무료 티어 60초"와 어긋남. 300이 실제로 적용되지 않으면 이력서 4단계 파이프라인과 평가 예산(240초)이 함께 무너짐|**미해결.** 현재 플랜·런타임의 실제 상한 확인 → 미달 시 단계 병합 / 모델 경량화 / 플랜 상향 중 선택|

### 9.2 미구현 — 문서에 기재됐으나 코드에 없는 항목

> v3.5 이하 문서에 "완료"로 기재돼 있었으나 실제 구현되지 않은 항목이다. 구현하거나 스펙에서 제외해야 한다.

- [ ] **리포트 4-상태 UI** — 서버는 `status`를 계산해 저장하지만 `AnswerReport` 타입과 `ReportView`가 이를 읽지 않음. 힌트/건너뜀/실패 답변이 화면에서 구분되지 않는다
- [ ] **단건 답변 재평가 API** (`type: "reevaluate"`) — 엔드포인트 없음. 위 4-상태 UI와 한 세트로 처리해야 진입점이 생김
- [ ] **JD 최소 50자 검증** — 면접 설정에 글자 수 검증 없음
- [ ] **이어하기 24시간 유효 기간** — 만료 로직 없음
- [ ] **히스토리 10회 초과 시 자동 삭제** — 조회 제한만 있고 삭제 없음
- [ ] **파싱 실패 시 텍스트 직접 붙여넣기 fallback** — UI 없음. 현재는 명시적 거부만
- [ ] **동일 타입 문서 재업로드 시 교체 확인** — 확인 절차 없이 병렬 보유
- [ ] **탭 닫기 경고(`beforeunload`) / `visibilitychange` 상태 저장** — 두 핸들러 모두 없음. 이탈 저장은 `handleExit()` 명시 호출만
- [ ] **스트리밍 응답 / 타이프라이터 UX** — `Response.json()` 일괄 응답

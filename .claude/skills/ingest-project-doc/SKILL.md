# Ingest Project Doc

> **이 스킬은 팀 작업의 구성 요소다.** 사용자 요청에서 직접 트리거됐고 작업이 단일 파일 수정보다 크면(수집·해석·기입·검증이 함께 필요하면) `portfolio-info-orchestrator` 를 먼저 검토하라. 혼자 기입하면 경계면 검증과 소유권 분리가 빠진다.


외부 마크다운을 `src/content/{project}/{slug}.md` 로 옮겨 **실제로 렌더되는 상태**까지 만드는 절차.

복사는 쉽고, 렌더되게 만드는 것이 일이다. `project-docs.ts` 가 런타임에 옵시디언 문법을 정규화하는데, 매핑에 없는 위키링크는 **에러 없이 평문으로 죽는다.** 복사만 하고 매핑을 빠뜨리는 것이 이 작업의 압도적 1위 실패다.

## 절차

### 1. 이식 범위를 정한다

원본 디렉토리의 문서 중 무엇을 올릴지 결정한다. 회의록·스크래치 메모는 보통 제외한다. 제외한 문서를 참조하는 링크가 생기므로, **제외 목록을 먼저 확정**해야 다음 단계에서 매핑과 `missingDocs` 를 한 번에 정리할 수 있다.

### 2. slug를 정한다

파일명이 곧 slug이고 URL(`/projects/{project}/{slug}`)과 `projects.ts` 의 `docs[].slug` 가 된다.
- 영소문자 + 하이픈만. 공백·한글·대문자 금지
- 내용 기반으로 짧게 (`회원_비회원 기능 구분` → `access-policy`)
- 한 번 정하면 URL·매핑·메뉴 세 곳에 박히므로 바꾸기 비싸다

### 3. 민감정보를 걸러낸다

이식 **전에** 훑는다. 공개 사이트로 나가는 내용이다.

```bash
grep -nE "sk-[A-Za-z0-9]{10,}|ghp_|xox[baprs]-|Bearer |PRIVATE KEY|010-?[0-9]{4}" {원본파일}
grep -nE "https?://[a-z0-9.-]*\.(internal|local|corp)" {원본파일}
```

고객사 실명·담당자 이름·미공개 계약 조건은 패턴으로 안 잡히므로 직접 읽는다. 제거하거나 일반화(`A 고객사`)하고, 제거 목록을 출력에 남긴다.

### 4. 본문을 그대로 옮긴다

내용·문체·수치·구조를 편집하지 않는다. 포트폴리오 문서의 가치는 **실제 작업 산출물이라는 점**에 있고, 다듬으면 그 가치가 사라진다. 손대는 것은 문법·링크·자산 참조뿐이다.

옵시디언 프론트매터(`---` 블록)는 제거한다 — 마크다운 뷰어가 본문으로 렌더해 버린다.

### 5. 위키링크를 전수 처리한다

```bash
grep -oh '\[\[[^]]*\]\]' src/content/{project}/*.md | sort -u
```

각 대상을 셋 중 하나로 분류한다:

| 분류 | 처리 |
|------|------|
| 함께 이식하는 문서 | `wikiTargetToSlug[{project}]` 에 `소문자 파일명: 'slug'` 매핑 추가 요청 |
| 이식하지 않는 문서 | `missingDocs[{project}]` 에 제목 추가 요청 → 참조 줄이 통째로 제거됨 |
| 어느 문서인지 불명 | 추측 매핑을 만들지 말고 `missingDocs` 후보로 올리고 사유를 남긴다 |

**매핑 키는 경로의 마지막 조각을 소문자화한 값**이다. `[[Playball/PRD]]` 의 키는 `prd`, `[[Micro Projects/Replai/Decisions]]` 의 키는 `decisions` 다.

표기 변형은 **모두 등록**한다. 원문에 가운뎃점(`·`), 마침표(`.`), 언더스코어(`_`)가 섞여 있으면 각각 별칭으로 넣는다:

```ts
'로그인.회원가입': 'auth',
'로그인·회원가입': 'auth',
'회원_비회원 기능 구분': 'access-policy',
```

잘못된 매핑은 깨진 링크보다 나쁘다 — 사용자를 엉뚱한 문서로 보내고, 아무 에러도 나지 않는다.

### 6. 이미지·자산을 판단한다

`![[image.png]]` 임베드는 정규화 단계에서 **제거**된다. 둘 중 하나를 택한다:
- 보여줄 가치가 있다 → 원본 이미지를 `src/assets/{project}/` 로 옮기고, 컴포넌트에서 쓰도록 리더에게 요청
- 없다 → 제거된 채로 둔다 (문서 본문에 빈 자리가 남지 않는지 확인)

마크다운 안에서 `src/assets/` 를 직접 참조하지 않는다. Vite 번들 경로가 되지 않아 깨진다.

### 7. 메뉴 등록을 요청한다

`src/data/` 는 portfolio-data-writer의 소유이므로 직접 고치지 않는다. 등록할 리터럴을 완성해 전달한다:

```ts
// projects.ts — docs 또는 docGroups 안에
{ slug: 'queue-policy', title: '대기열 정책' },
```

`title` 은 메뉴에 그대로 노출되므로 원문 제목을 쓴다. 문서 4~5개를 넘고 성격이 갈리면 `docGroups` 로 묶도록 그룹명까지 제안한다.

신규 프로젝트라면 `project-docs.ts` 의 glob 블록·`sourcesByProject`·`wikiTargetToSlug` 프로젝트 키 추가도 함께 요청한다. 빼먹으면 메뉴는 보이고 본문은 전부 빈다.

### 8. 검증한다

```bash
node .claude/skills/verify-portfolio/scripts/check-integrity.mjs
```

이식 직후 바로 돌린다. 전체 작업이 끝난 뒤에 돌리면 slug 결함 하나를 고치려고 문서·데이터·매핑 세 곳을 되돌려야 한다.

## 자주 나는 결함

| 증상 | 원인 |
|------|------|
| 메뉴 항목을 눌렀는데 빈 페이지 | `docs[].slug` 와 파일명 불일치, 또는 신규 프로젝트의 glob 미등록 |
| 문서는 보이는데 내부 링크가 평문 | `wikiTargetToSlug` 매핑 누락 |
| 링크를 눌렀는데 빈 문서 | 매핑 값이 실존하지 않는 slug (죽은 매핑) |
| 문서 중간에 빈 줄만 남음 | 이미지 임베드가 제거됐으나 자산을 옮기지 않음 |
| 참조 목록에 못 누르는 항목 | 이식하지 않은 문서인데 `missingDocs` 에 없음 |

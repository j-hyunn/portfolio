# Collect Source

> **이 스킬은 팀 작업의 구성 요소다.** 사용자 요청에서 직접 트리거됐고 작업이 단일 파일 수정보다 크면(수집·해석·기입·검증이 함께 필요하면) `portfolio-info-orchestrator` 를 먼저 검토하라. 혼자 기입하면 경계면 검증과 소유권 분리가 빠진다.


GitHub 저장소나 마크다운 문서에서 포트폴리오에 쓸 사실을 긁어내는 절차.

## 수집 원칙

해석하지 말고 **망라한다.** 이 단계에서 빠진 사실은 하류에서 복구되지 않는다. 반대로 이 단계에서 추측으로 채운 값은 하류 전체가 사실로 믿는다. 그래서 두 가지만 지킨다: 빠뜨리지 않기, 만들어내지 않기.

모든 사실에 출처를 붙인다. 출처를 쓸 수 없으면 그 문장은 추측이므로 `[추정]` 을 붙이거나 버린다.

## GitHub 저장소 수집

읽는 순서 — 신뢰도가 높은 것부터:

1. `README.md` — 프로젝트 정의, 문제의식, 스택. 가장 신뢰할 수 있는 1차 자료
2. `docs/`, `*.md` — PRD·설계 문서. 산출물 후보이기도 하다
3. `package.json` / `requirements.txt` / `go.mod` — 기술 스택의 **사실상 정본**. README의 스택 서술과 어긋나면 양쪽을 병기한다
4. 디렉토리 구조 — 아키텍처 추론 근거
5. 커밋 이력 — 기간의 사실상 정본. `git log --reverse --format='%ad %s' --date=short | head -1` 로 시작일, 마지막 커밋으로 종료일/운영 중 여부
6. PR·이슈 — 협업 규모, 의사결정 근거

```bash
gh repo view {owner}/{repo} --json name,description,createdAt,pushedAt,languages,topics
gh api repos/{owner}/{repo}/contributors --jq '.[] | {login, contributions}'
```

**기간과 팀 규모는 추측하지 않는다.** 커밋 이력과 contributor 목록이 사실이고, 그것으로 설명되지 않는 것은 `미확인` 이다. "14인 팀 프로젝트" 같은 값은 사용자 확인 사항이다.

접근 실패(private·404) 시 1회 재시도하고, 그래도 안 되면 로컬 클론 경로를 요청한다. 저장소 이름만 보고 내용을 지어내는 것은 최악의 실패다.

## 옵시디언 · 로컬 마크다운 수집

1. 디렉토리 전체 목록을 먼저 뽑는다 (`find {dir} -name '*.md'`)
2. 각 파일의 제목(첫 `#`)과 분량(`wc -l`)으로 성격을 분류한다: PRD / TRD / 기능 명세 / 정책 / 회의록 / 잡메모
3. 본문은 **원문 그대로** 보존한다. 옵시디언 문법(`[[링크]]`, `![[이미지]]`, 프론트매터)을 정리하지 않는다 — 정규화는 doc-ingestor의 일이고, 여기서 손대면 원문과 이식본의 차이를 추적할 수 없다
4. 문서 간 `[[링크]]` 그래프를 뽑아둔다. 어느 문서가 어느 문서를 참조하는지가 이식 범위 판단의 근거가 된다

```bash
grep -oh '\[\[[^]]*\]\]' {dir}/*.md | sort | uniq -c | sort -rn
```

회의록·잡메모는 포트폴리오 산출물로 적합하지 않은 경우가 많다. 제외를 권고하되 판단은 info-curator에게 넘긴다.

## 성과 지표 추출

포트폴리오에서 가장 가치 있고 가장 조작되기 쉬운 정보다.

- 수치는 **원문 표현 그대로** 인용한다. 단위·기준 시점을 바꾸지 않는다
- 측정 방법이 함께 적혀 있으면 반드시 같이 가져온다 (`GA4 이벤트 기준`, `3개월 평균`). 방법 없는 수치는 `[측정 방법 미확인]` 을 붙인다
- 상대값만 있으면(`2배 개선`) 절대값을 찾아본다. 없으면 상대값만 기록한다
- 추정치·목표치를 실적으로 바꾸지 않는다. 원문이 "목표"라면 `[목표치]` 로 표시한다

## 민감정보 필터

수집 단계에서 걸러야 하는 것 — 이 정보는 공개 사이트로 흘러간다:

- API 키·토큰·비밀번호·`.env` 내용 → 값은 기록하지 않고 `[민감정보 제외]` 로만 표기
- 사내 URL·내부 호스트명·IP
- 고객사 실명, 담당자 이름·연락처
- 미공개 매출·계약 조건

판단이 애매하면 기록하되 `[공개 여부 확인 필요]` 를 붙여 사용자 판단을 받는다. 조용히 넣는 것보다 조용히 빼는 것이 낫고, 둘 다보다 물어보는 것이 낫다.

## 출력

`_workspace/02_collector_{source-name}_raw.md` 에 `source-collector` 에이전트 정의의 출력 구조로 저장한다. 여러 출처를 수집하면 출처별로 파일을 나눈다 — 한 파일에 섞으면 충돌한 사실의 출처를 잃는다.

마지막에 `## 미확인 항목` 을 반드시 채운다. 비어 있는 미확인 목록은 "전부 확인됨"이 아니라 "확인하지 않았음"을 뜻하는 경우가 대부분이다.
